## 哪些改动影响了成绩

- 第二轮与第三轮只差 **0.0319** 分，但两者擅长的电路不同。第三轮在 ariane 上领先第二轮 **15.45** 分，第二轮在另两张电路都更高。第四轮的 ariane / 1003 从第二轮的 **82.90** 降至 **16.80**，这一组就拉低九组均分约 **7.34** 分。
- 第五轮有两种不同的 −100。bp-ng45 / 1002 在图训练后、布局阶段丢失 GPU，官方罚 −100，原始分为空。部署备用任务时恰好重载了系统服务，很可能触发这次故障。下一组的新容器已恢复。ariane / 1001 正常完成物理计算，原始分 **−111.58**，按规则计 −100。即使把故障组按 +100 估算，第五轮上限也只有 **25.02**，因此没有占用 GPU 单独重跑。
- 第六轮已完成的六个种子与第一轮对应种子的计入分逐一相同。尚未出分的 ariane 正是前几轮波动最大的电路，整轮结论要等最后三组。

## 实验怎样改变搜索策略

3090 当前版本前六轮都从官方初始程序生成候选。它把单个算例或种子主导的收益留作最终选分参考，只有收益分布更广时才沿用该候选作为父代。这使第二轮有 **23.42** 分、第三轮有 **23.39** 分时，第四轮仍然从官方起点试另一个解码器。

我用实际前三轮的训练回执回放了已部署的备用版本 `27f29c9`。它在同一处会把**第三轮的损失函数和第二轮的解码器**组合起来，合成程序已通过官方静态接口检查，两部分的单独收益都主要来自 ariane，组合效果仍待正式物理评估。备用版的正式运行会从官方初始程序开始，只使用自己收到的回执。
